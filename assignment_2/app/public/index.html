⚠️ Why does "In execution nothing work" happen in n8n?

n8n operates in two distinct execution modes. If configured incorrectly, incoming requests return HTTP 404 and will NOT appear in the Executions tab:

1. Production / Active Mode (Required for the "Executions" tab)
  • Look at the top-right corner of your n8n canvas (next to "Save").
  • Flip the switch from Inactive ◯────── to Active ──────◯.
  • When Active, n8n listens 24/7 on /webhook/generate-royalty-summary and logs every trigger in Executions in the left sidebar!
2. Canvas Test Mode (To watch nodes turn green interactively)
  • Leave the switch on Inactive.
  • Click "Test workflow" at the bottom of the n8n canvas. n8n will say "Waiting for webhook call...".
  • In this state, n8n only listens on /webhook-test/generate-royalty-summary.
  • Our companion app automatically detects this and routes requests to /webhook-test/ so your canvas animates!

1. Relational Database Design in Bubble

We structure the Bubble database using clean 1:Many relationships, mirroring a production PostgreSQL database:

Data Type: Author
  • author_id (text) • Unique business identifier
  • name (text) • Full author name
  • email (text) • Authentication username
  • phone (text) • Contact phone number
  • city (text) • City of residence
  • joined_date (date) • Account registration date
  • books (List of Books) • Relational link
  • user_type (text: Author | Admin)
Data Type: Book
  • book_id (text) • Unique catalog ID
  • author (Author) • Parent relational reference
  • title (text) • Book title
  • isbn (text) • Unique assigned ISBN
  • genre (text) • Catalog genre
  • publication_date (date) • Release date
  • status (text) • Published & Live / In Production
  • mrp (number) • Retail price
  • author_royalty_per_copy (number) • Contract rate
  • total_copies_sold (number) • Units sold
  • total_royalty_earned (number) • Accrued
  • royalty_paid (number) • Disbursed
  • royalty_pending (number) • Outstanding
  • last_royalty_payout_date (date) • Timestamp
  • print_partner (text) • In-House, Repro India, etc.

2. Bubble Privacy Rules (Data Isolation)

Ensures author-type users are strictly sandboxed to their own titles, while administrators retain catalog-wide oversight:

Data Type Condition Permissions Granted
Author Current User's Role is Admin View all fields, Searchable in queries
Author This Author's Email is Current User's Email View all fields, Edit profile
Author Everyone Else (Public) No access (Strictly hidden)
Book Current User's Role is Admin View all fields, trigger workflows
Book This Book's Author's Email is Current User's Email View all fields
Book Everyone Else (Public) No access

3. Bubble Status Badge Conditionals

  • Green : This Book's royalty_pending is 0
  • Yellow : This Book's royalty_pending > 0 and (Current date/time - This Book's last_royalty_payout_date):days < 90
  • Red (Overdue) : This Book's royalty_pending > 0 and (Current date/time - This Book's last_royalty_payout_date):days ≥ 90 OR (This Book's last_royalty_payout_date is empty and (Current date/time - This Book's publication_date):days > 90)
